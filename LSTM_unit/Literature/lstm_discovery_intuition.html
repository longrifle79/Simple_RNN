How We Invented LSTM
at the Kitchen Table

A step-by-step story of the questions we asked, the simple ideas we tried, why they failed, and how each failure forced us to invent the next piece of the solution — all while staring at a single time series chart.

The Scene

Imagine we are sitting at a sturdy wooden table in a quiet room with good light. On the table is a large printed line chart showing a time series. We have markers, a small whiteboard, coffee, and a notebook. Our goal is simple but stubborn:

"Predict the next value on this chart as accurately as possible."

We will proceed exactly as curious people would: ask naive questions, try the simplest possible ideas, watch them fail in specific and revealing ways, and let each failure tell us what the next component must do.

We have a time series chart and a shared desire to understand why each piece is needed.

1. The Problem & The First Questions We Asked

We start with a concrete time series. Here is the chart we are looking at (synthetic but realistic — it contains a gentle trend, seasonality, and a clear regime shift around step 45 so we can see what happens when the world changes):

The task:

Given the values up to time \( t \), predict the value at \( t+1 \).

The first questions we wrote on the whiteboard:

  • Does the future depend on the past at all?
  • If yes — how much of the past? All of it, or only the recent few steps?
  • What if the underlying process changed partway through (new policy, competitor, sensor drift)?
  • How do we even represent "memory" of the past inside a prediction system?

2. Attempt #1 — Using Only Long-Term Memory

Attempt #1

Someone at the table says: "Let's just use everything we've seen so far. The long-term average should be stable and reliable."

What it looks like mathematically

\[ \hat{x}_{t+1} = \frac{1}{t} \sum_{i=1}^{t} x_i \qquad \text{(cumulative mean)} \]

Or an exponentially-weighted version that still gives significant weight to the entire history.

Why it fails (shown on our chart)

After the regime shift (around step 45), the predictor is still heavily dragged down by all the old low values. It takes dozens of steps to "catch up". The prediction systematically lags behind reality whenever the series is non-stationary.

Analogy: Trying to steer a ship using only the average position of every port you have ever visited in your entire life. When you sail into a completely new ocean, you are still averaging in the old harbors from decades ago.

Diagram — The Long-Term Memory "Bucket"

No mechanism exists to forget what is no longer true.

Key insight we wrote on the whiteboard:
Long-term memory alone is too rigid. It cannot forget what is no longer true. We need a way to selectively discard old information.

3. Attempt #2 — Using Only Short-Term Memory

Attempt #2

"Okay, the long-term average is too slow to adapt. Let's only look at the most recent few points. Yesterday and the day before should be most relevant."

What it looks like

\[ \hat{x}_{t+1} = x_t \qquad \text{(last value)} \quad \text{or} \quad \frac{1}{N}\sum_{i=0}^{N-1} x_{t-i} \quad (N=3\text{–}5) \]

It completely forgets any pattern that occurred more than N steps ago. If the series has long-range dependencies (seasonality, slow cycles, or an important event from 30 steps ago that still matters), short-term memory is blind to it. On our chart it zig-zags with noise and misses the bigger structure.

Analogy: Having the memory of a goldfish. You remember the last few seconds perfectly, but you have no idea why you swam into this part of the tank or what the seasonal current patterns are.

Diagram — The Short-Term Window That Falls Off the Edge

Key insight on the whiteboard:
Short-term memory alone is too forgetful. It throws away the long-term structure we need. We need a way to preserve important information across many time steps.

4. The Realization — We Need Both, But With Control

At this point someone at the table says:

"We need the stability and long-range information of long-term memory AND the quick adaptability of short-term memory. But if we just add them or concatenate, the old information pollutes the new, and the new information can overwrite important old patterns."

The new questions that naturally arise

  • What if the memory could mostly stay the same (long-term preservation) but we could choose to add a little new information or choose to forget some old information at each step?
  • Who or what decides what is worth remembering and what should be forgotten?
  • How do we make that decision using only the information available right now (current input + what we currently remember)?
This is the pivotal moment. We realize we need a memory cell whose content persists across time with almost no change (the "constant error carousel"), but is protected and updated by learned gates that act like valves.

5. Building the LSTM Cell — One Component at a Time

We start with the idea of a memory cell that runs through time like a conveyor belt or highway. Information can stay on the belt for a long time with almost no distortion. At each time step we can open small "valves" (gates) to add new cargo or remove old cargo.

The Cell State Highway (the key intuition)

5.1 The Forget Gate — Why we need it

We need a way to discard information from the cell state that is no longer relevant (the old regime before the shift in our chart).

Analogy: A meticulous librarian who periodically reviews the filing cabinet and throws away documents that are no longer useful, but only after checking the current context (the new input and what we currently remember).
\[ \text{net}_{f,t} = w_{xf} x_t + w_{hf} h_{t-1} + b_f \]
\[ f_t = \sigma(\text{net}_{f,t}) \quad \text{(values between 0 and 1)} \]

The previous cell state is multiplied element-wise by \( f_t \). When \( f_t \approx 0 \), old information is forgotten; when \( f_t \approx 1 \), it is preserved.

Why we needed the forget gate: Without it, the cell state would keep accumulating old information forever — exactly the long-term memory problem we saw earlier.

5.2 The Input Gate + Candidate — Why we need them

We also need a way to add new, relevant information into the cell state without letting in every noisy fluctuation.

\[ \text{net}_{i,t} = w_{xi} x_t + w_{hi} h_{t-1} + b_i \]
\[ i_t = \sigma(\text{net}_{i,t}) \]

\[ \text{net}_{g,t} = w_{xg} x_t + w_{hg} h_{t-1} + b_g \]
\[ g_t = \tanh(\text{net}_{g,t}) \quad \text{(candidate values)} \]
Cell update:
\[ c_t = f_t \odot c_{t-1} + i_t \odot g_t \]
Analogy: The same librarian deciding which new memos are important enough to file, and in what summarized form.
Why we needed the input gate + candidate: Pure long-term memory could not incorporate new signals quickly; pure short-term memory had nothing stable to build upon.

5.3 The Output Gate — Why we need it

Even if the cell state contains perfect long-term + short-term information, we may not want to output all of it for the current prediction. Some information might be relevant for future steps but not right now.

\[ \text{net}_{o,t} = w_{xo} x_t + w_{ho} h_{t-1} + b_o \]
\[ o_t = \sigma(\text{net}_{o,t}) \]

\[ h_t = o_t \odot \tanh(c_t) \]
Analogy: The librarian preparing a summary report for the boss — they do not dump the entire filing cabinet; they select only what is relevant for this decision.
Why we needed the output gate: It filters what is useful for the current prediction while keeping other information protected inside the cell for later use.

\( w_{xo_{t-1}} = 0.4 \)

What the gates are doing in this step

  • Output gate \( o = 0.5250 \): moderately open — it lets through about half of the cell state's information.
  • The cell state \( c \) is being read but not modified by this weight (that's why the gradient path for \( w_{xo} \) is simple — no extra cell-state branch).
  • Prediction \( h = 0.1426 \) is too low compared with target 0.8 → we will push \( w_{xo} \) upward.

8. Key Takeaways — Why the Gates Exist

Forget Gate
Solves the "old information pollutes forever" problem of pure long-term memory. It gives the cell a way to reset or down-weight stale content.
Input Gate + Candidate
Solves the "can't adapt to new information" problem. It lets the cell incorporate fresh signals without being overwhelmed by noise.
Output Gate
Solves the "too much irrelevant information flowing to the prediction" problem. It selects what the current output actually needs from the rich cell state.

The beautiful part:

Every gate exists because of a concrete failure mode we discovered while sitting at the table trying to predict the next point on a chart. The architecture is not arbitrary — it is the minimal machinery required to solve the problems we actually encountered.
